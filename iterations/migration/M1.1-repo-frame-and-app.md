## 4. Tasks

### 4.1 Make the integration branch with both histories
```
git fetch shared                                   # remote for github.com/brocks01/Bricks
git switch -c sayan/migration shared/main          # start from the shared main
git switch -c sayan/frame shared/sayan             # our code
#   on sayan/frame, move our files to where they will live (one commit, "move only"):
#     app/                  → app/                 (unchanged path)
#     backend/              → backend/legacy/      (moved into modules in M1.2)
#     docs/, iterations/    → team-docs/11-bricks-app/   (renamed in M4.1)
#     CHANGELOG.md          → team-docs/11-bricks-app/CHANGELOG.md
git switch sayan/migration
git merge --allow-unrelated-histories sayan/frame  # both histories kept
```
Conflicts expected only where both sides have a file at the same path:

| Path | Keep |
|---|---|
| `app/**` | **Ours** (the decision). The shared app is still in history and on `main` |
| `README.md` | The shared one, plus a short "Bricks app" section pointing at `team-docs/11-bricks-app/` |
| `.github/workflows/*` | Both: the shared `ci.yml`, plus our `app.yml` and `backend.yml` renamed `app-legacy.yml`, `backend-legacy.yml` until M4.1 |
| `.gitignore` | Union of both (ours lists `Luma ios Sep 2026/`, `.env.local`, `app/dist`) |

### 4.2 Things the shared app had that ours needs to keep working
- `app/vercel.json` (website deploy): keep the shared file if the website is still deployed from `app/`; check it
  builds our app (`npx expo export --platform web`).
- The shared backend serves `app/dist` at `/` (`main.py`, `_DIST`): our web build must go to the same folder.
- Ports: the shared app runs the website on **3000** ("the only one Google accepts for sign-in"). Our app's web
  script must use 3000 too (needed from M2.2 on).

### 4.3 Env examples
- `app/.env.example`: our names; mark the Supabase ones "removed in M2.2".
- `backend/.env.example`: the shared one plus our names that stay (WhatsApp, storage, Google speech, Gemini text),
  in a section "Bricks app modules". Names only, never values.
