Phase M3 · Est. **4 h** · Source: [M3.1](M3.1-live-voice-backend.md); shared `backend/app/modules/agent/router.py` (`WS /v1/agent/live`), shared app `src/agent/live.ts`, `audio.web.ts`

| | |

## 2. Entry criteria
- [ ] [M2.2](M2.2-identity-app.md) done (the live talk signs in with the shared token).

## 3. Scope
**In:** keeping Buddy on phones, the browser live talk, mapping our actions.
**Out:** live talk **on phones**. It needs a native module that streams microphone audio and plays audio as it
arrives, plus a new dev build; neither codebase has one (the shared app types on phones too). A later iteration.

## 4. Tasks

### 4.1 Buddy on phones: unchanged
- Buddy still records, sends to `/v1/assistant/transcribe`, and acts on the result with its local intents
  (`features/buddy/intents.ts`). Only the base address changed (M1.2) and the token (M2.2).
- The answer path that used `/assistant/turn` (removed in M3.1): Buddy's local intents already cover open a screen,
  start/stop a walk, today, reminders, join; anything else gets the "I can help with ..." reply in the person's language.

### 4.2 Live talk in the browser
- Port the shared client: `src/agent/live.ts` (the socket and its protocol) and `audio.web.ts` (16 kHz microphone up,
  24 kHz playback down) into `src/features/buddy/live/`. `audio.ts` for phones reports "not available", so Buddy falls
  back to 4.1 there.
- First message `{type: "auth", token, page, tools}` with the shared access token and our tools (4.3).

### 4.3 Our tools for the in-app talk
The shared app hands the model its page tree; ours hands it the actions Buddy already has (our `UiAction` contract):

| Tool | Runs | Confirmation |
|---|---|---|
| `open_screen` (`screen`: one of Buddy's screen names) | In the app: navigate | No |
| `start_walk`, `finish_walk` | In the app | No |
| `read_screen` | In the app: the screen's Read it out script | No |
| `today`, `events` | On the server (M3.1 tools) | No |
| `set_reminder`, `join_event` | On the server | **Yes**: our `ConfirmSheet` in the app, then `toolResult` |

- `modules/agent/router.py`: our server tools join `SERVER_TOOLS`; our system prompt replaces the shared one for our app.
- The distress check (M3.1 §4.2) runs on the `person` text here too, and opens our SOS screen in the app.

### 4.4 Design system
- Every new word in the four language files; the live talk's sheet built from our components (`ListeningSheet`,
  `ConfirmSheet`), so the lint rules pass.
