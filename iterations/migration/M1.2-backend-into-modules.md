## 4. Tasks

### 4.1 Core
- `core/async_db.py`: our pool (`psycopg_pool.AsyncConnectionPool`, one transaction per request) and the `Conn`
  type, next to the shared sync `core/db.py`. Both read the same `DATABASE_URL`.
- Our settings (`config.py`, pydantic-settings) become `core/bricks_settings.py`; the shared `core/config.py` loads
  `backend/.env` first, so both see the same values.
- `ids.py`, `timeutil.py`, `geo.py`, `storage.py` → `core/`. `deps.py` (`Ctx`, `CtxDep`) → `core/ctx.py`.
- On Windows our pool needs the selector event loop: `backend/run.py` sets it before starting uvicorn (what our
  `python -m bricks_api` does today).

### 4.2 Modules
- One folder per row of the module map: `router.py` (our router file, prefix `/v1`), `service.py` (the functions our
  routers call, out of `repo.py` and the routers), `schemas.py` (the models from our `schemas.py` that module uses).
- Shared schema models used by several modules (`EventSummary`, `Person`, ...) go in `core/schemas.py`.
- The shared rule "a module only imports another module's `service.py`" holds for new imports; where ours imports a
  router's function today (for example `thrive.today` from the assistant), point it at that module's `service.py`.
- `main.py`: include our routers beside the shared ones, in the same style.

### 4.3 Migrations
- Our `001`–`005` become `0015_bricks_init.sql` … `0019_bricks_health_card_stories.sql`, applied by the shared
  startup applier (`schema_migrations`).
- **Name clashes** with the shared tables in `public` (`users`, `family_invites`): for M1 our tables stay in the
  schema **`bricks`** (as today): each file starts with `create schema if not exists bricks; set search_path = bricks;`
  and our async pool keeps `search_path=bricks`. M2.1 removes the clash.
- Our `migrate.py` (add-only) is retired; the shared applier runs each file once.

### 4.4 Dependencies
- Add ours to `backend/requirements.txt` (exact pins from our `uv.lock`): `psycopg[binary]`, `psycopg-pool`,
  `pydantic-settings`, `pyjwt[crypto]`, `twilio` (until M3.1), the Google speech and Gemini clients, `anyio`.
- Check the two FastAPI and pydantic versions agree (shared `fastapi==0.141.1`); take the higher one and run both
  test suites.

### 4.5 Tests
- Our `tests/` → `backend/tests/<module>/`; our `conftest.py` fixtures (the `bricks_test` schema) beside the shared
  ones. Both suites run with one `python -m pytest tests -q`.
- ruff and mypy run on `backend/app/modules/<ours>` (configs from our `pyproject.toml` moved into `backend/ruff.toml`
  and `backend/mypy.ini`), if Q11 said yes.

### 4.6 The app
- `EXPO_PUBLIC_API_URL` ends in `/v1` (one line in `.env.local`, and the EAS environment). No other app change.

### 4.7 Remove `backend/legacy/`
- Once T1–T4 pass, delete the parked folder in the same pull request.

## 8. Risks and fallbacks

| Risk | Fallback |
|---|---|
| Version clash (FastAPI, pydantic, httpx) | Pin to what both suites pass; note it in `PROGRESS.md` |
| Async and sync pools exhaust the Supabase pooler's connections | Lower both pool sizes (shared `pool_size=10, max_overflow=20` is high for the free pooler) |
| Splitting `repo.py` across modules creates import cycles | Keep shared query helpers in `core/queries.py` for now |
