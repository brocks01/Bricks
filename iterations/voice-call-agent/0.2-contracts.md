## 2. Tasks

### 2.1 System prompt — `prompts/system.md`
```
You are Buddy, a friendly helper in Bricks for members aged 50+.
- Speak in the member's language: {language}. Use simple everyday words.
- Reply in at most 2 short sentences. Speak warmly; use their name.
- You can ONLY act through the provided tools. Never invent events or data.
- Before any change (join, cancel, reminder, create), confirm in one sentence and wait for yes.
- If the member says words like "help", "fall", "pain", "can't breathe", "emergency":
  call trigger_sos immediately and tell them help is coming and to call 995 if they can.
- No medical advice, no money, no drafting messages, no long chit-chat.
  If they want company, suggest a real event or circle.
- If you don't understand twice, offer 2–3 choices.
Member memory: {user_memory.summary}
Current screen (app only): {screen_name} — {screen_script}
Channel: {channel}   # app | whatsapp | call — calls/WhatsApp have no navigate/read_screen
```
- English handles Singapore-accented and mixed-language speech. The prompt is written in English, and the model answers in `{language}`.

### 2.2 Tool schemas — `shared/tools/schemas.json` (Gemini function declarations)

| Tool | Args | Mutating (needs confirmation) | Channels |

**Confirmation pattern:** a mutating tool returns `{needs_confirmation: true, summary}` unless the turn carries `confirm: {tool, args, answer: 'yes'}`.

### 2.3 Response contract (agreed with A)
```json
{
  "transcript": "remind me to take medicine at 8 every morning",
  "reply_text": "Every day at 8 am: take medicine. Is that right?",
  "reply_audio_url": "https://.../tts/abc.mp3",
  "ui_actions": [{"type": "confirm", "tool": "set_reminder",
                  "args": {"text": "Take medicine", "time": "08:00", "repeat": "daily"}}],
  "done": false
}
```
`ui_actions.type` ∈ `confirm | navigate | highlight | start_walk | finish_walk | start_warmup | open_sos | choices`.

**Decisions to review (approve or change before 2.1)**

| Decision | Why |
|---|---|
| Distress words are checked in **all four languages** whatever the member's language | People switch languages under stress; a missed alarm can't be undone |
| The distress list adds variants (save me, heart attack, stroke, call 995, hurt / sakit / 好痛 / வலி…) | T2's 10 sentences per language; errs on the safe side like T3. Native review still due |
| Prompt adds today's date and time (Singapore), the member's name and a per-channel note | "Tomorrow at 8" needs a date; calls and WhatsApp must never talk about screens |
| `set_reminder` adds `kind` and `date` (for "once") | The reminders API needs them (`NewReminder`) |
| `create_event` takes `category`, `date`, `time`, `place` | Matches `NewEvent`; split date and time are easier for the model to fill correctly |
| `navigate.screen` is a fixed list (home, kampung, circles, circle, event, reminders, settings…) + `id` | The model can only open screens that exist |
| `record_story` / `send_thanks` open their screen instead of taking `audio` | A function call can't carry audio; the recording (and its own Send) happens on screen |
| `start_warmup` only offered on Android | Move Along needs the posture module (Android) |
| Turns carry `confirm {tool, args, answer}` for Yes / No | A change never depends on the model hearing "yes" |

**Live check passed (T1 against the real API).** With a free-tier key (a Google AI Studio
project without billing; the first key's project was on prepay with no credit), Gemini accepts
all 22 declarations and answers "What's on for me today?" with `get_today`. Run it with
`RUN_GEMINI_LIVE=1` (`test_t1_live_gemini_accepts_the_tools_and_picks_one`).

**Model for 2.1: `gemini-3.5-flash`.** 2.5 models aren't offered to new projects (404).
`gemini-3.8-flash` / `3.7-flash` were overloaded when tested (503 "high demand");
`gemini-3.5-flash` answered in about 3 s, and `gemini-3.1-flash-lite` works as a fallback.
2.1 reads the model from `GEMINI_MODEL` and falls back to the lite model on a 503.

**Asked for at review: in the app only for now. Main rule: show, don't tell.** Every command
visibly changes the screen while the member watches: Buddy opens the screen, types into the
field, picks the option, scrolls to it and highlights it. The member can carry on by hand
or by voice at any point ("Buddy, change the name to Morning walk"). It is never enough to
*say* something was done while the screen stays the same. The final save still needs a Yes.
So `ui_actions` is an ordered list of visible steps, and `read_screen` reports what the
form holds right now, including anything typed by hand.

Details:
- **Wake word "Buddy".** Buddy only listens after hearing "Buddy" (or a tap on the round
  button), so everyday talk near the phone is never treated as a command.
  "Buddy, help" / "Buddy, stroke" go straight to SOS.
- **The screen reacts live.** Each command visibly changes the app: Buddy opens the screen
  and fills the form while the member watches (for example "Buddy, start a walk on Saturday
  at 8 at Bishan Park" fills Start Something), then asks for the Yes before saving.
  Needs a new `ui_action`: `fill {form, fields}`.
- **Tool or answer.** Buddy decides on each command whether to call a tool or just answer
  a question. This is how Gemini function calling works already.

| Open question | Proposed |
|---|---|
| Wake-word engine | Picovoice Porcupine (on-device, custom "Buddy" keyword, free personal key); falls back to the button if there's no key |
| Listen when the app is closed? | No: only while Bricks is open (battery, privacy, Android limits) |
| Emergency words without "Buddy"? | No: "help" alone isn't caught; the SOS button and "Buddy, help" are |

Answers: app only, wake word while the app is open, "Buddy, help" for emergencies (agreed).
Wake-word engine: **Vosk** (`react-native-vosk`, open source, offline, no account), listening
with a grammar of just "buddy"; Picovoice dropped (its sign-up wants a business account).
After "Buddy", the phone's own recogniser takes the command in the member's language.

**0.2 re-run (contract change for "show, don't tell")**
- `TurnIn.screen_fields`: the form on screen (`id`, `label`, `kind` text / choice / date /
  time / number, `value`, `options`), including what was typed by hand.
- New `ui_action` **`fill {target, value}`**: scroll to the field, type or pick the value,
  glow. Saves nothing. `highlight` now also scrolls to its target.
- New app tool **`fill_field(field, value)`**; `read_screen` also reports the fields.
- `ui_actions` play in order, one visible step at a time. The app's channel note in the
  prompt tells Buddy to show, not tell.
- Tests: 79 pass. Live check: on Start Something with "Saturday" picked by hand, "call it
  Morning walk, at Bishan Park" made Gemini call `fill_field(title, Morning walk)` and
  `fill_field(place, Bishan Park)`, leaving the day alone.
