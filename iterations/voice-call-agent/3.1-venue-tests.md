## 1. At a glance

| | |
|---|---|
| **Goal** | Calls and Buddy work in the venue's acoustics and on its networks; the stage call is rehearsed |

## 2. Tasks

### 2.1 Call quality and latency
| Check | How | Target |
|---|---|---|
| Turn latency | Stopwatch from end of speech → start of reply, 10 turns | ≤ 2 s typical (Tier 1) |
| Recognition in the hall | Call from the stage area with crowd noise | Correct intent for "What's on today?" and "Remind me…" |
| Networks | Two mobile carriers (and Wi-Fi calling off) | Both clear |
| Speaker phone | Call on speaker for the audience | Prompts audible; recognition still OK |

Adjust: `speechTimeout`, shorter prompts, a slower TTS rate, and `enhanced` / `phone_call` speech models where Twilio offers them.

### 2.2 Buddy at the venue
- `/assistant/turn` latency on venue Wi-Fi vs hotspot. If it's slow, enable the keyword pre-router flag for core intents.

### 2.3 Stage call script (rehearse once)
```
Presenter dials (speaker on):
Buddy:  "Hi Raj! It's Buddy from Bricks. What would you like to do? ..."
Raj:    "Remind me to take my medicine at 8."
Buddy:  "Every day at 8 am: take medicine. Is that right?"
Raj:    "Yes."
Buddy:  "Done. I'll remind you every day at 8 am. See you at the walk tomorrow at 7!"
→ App on the projector: Reminders shows "8 am Take medicine"
```
- Use the team phone registered as Raj (caller-ID match).

### 2.4 Judge call path
- An unknown judge number → language menu → greeting works. A pre-registered judge number → member greeting.

## 3. Risks and fallbacks

| Risk | Fallback |
|---|---|
| Hall too noisy | Step off-stage for the call, or use DTMF for "yes"; backup recording |
| Carrier issue | Second phone on a different carrier |

## 4. Definition of Done
- [ ] Latency and recognition measured and acceptable
- [ ] Stage script run end-to-end once with the app updating
- [ ] Judge call path verified
