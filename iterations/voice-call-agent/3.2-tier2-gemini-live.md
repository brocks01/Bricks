## 2. Architecture
```
Caller ⇄ Twilio ── <Connect><Stream url="wss://…/voice/stream"> ──► Media Streams websocket
                                                   (μ-law 8 kHz frames, base64)
/voice/stream (FastAPI websocket)
   ├─ decode μ-law → PCM16 → resample 16 kHz → Gemini Live session (audio in)
   ├─ Gemini Live audio out → resample 8 kHz → μ-law → Twilio "media" messages
   ├─ barge-in: on caller speech start → send Twilio "clear" + interrupt Gemini output
   ├─ function calls from Gemini Live → same tools.run(user, call) + confirmation rules
   └─ parallel transcript tap → distress pre-check → trigger_sos (deterministic)
```

## 3. Tasks
1. **TwiML switch** in `/voice/incoming`: if `TIER2_ENABLED` for this number → `<Connect><Stream>`; else Tier 1.
2. **Websocket bridge**: handle Twilio `start` / `media` / `stop` events; audio transcoding (`audioop` / numpy); keep the session per `streamSid`.
3. **Gemini Live session** with the system prompt (`05` §1), the user memory, and the tools minus app-only ones; the voice in the user's language.
4. **Tools**: map Live function calls → `tools.run`; mutating tools must still ask "Is that right?" before executing (enforced server-side, not just by the prompt).
5. **Distress**: run on Gemini's input transcription; on a match → `trigger_sos` immediately and speak the sos_confirm prompt.
6. **Logging**: transcripts only; no audio stored.
7. (Future note only) background-sound / fall-thud detection on the stream: roadmap, not built.
