### 3.3 Inbound call loop — Tier 1, English (C1.3b)

**Flow**
```
POST /voice/incoming
  caller = lookup(From)
  known   → <Play inbound_welcome.known.en> + <Gather input="speech dtmf" language="en-SG"
             speechTimeout="auto" action="/voice/turn">
  unknown → language menu (DTMF 1–4) → (English only this iteration) → short greeting

POST /voice/turn  (SpeechResult, Digits, CallSid)
  if distress(SpeechResult) → trigger_sos → <Play sos_confirm> → end (or offer connect)
  intent = keywords(SpeechResult) or assistant stub
  today   → get_today → read 1–3 items → "Want to join the walk?"
  join    → confirm → join_event → "Done! I'll remind you at {time}."
  remind  → parse text/time → confirm ("Every day at 8 am: take medicine. Is that right?")
            → yes → set_reminder → writes a reminders row (shows in the app)
  else    → "Sorry, I didn't catch that." + offer choices
  silence 5 s ×2 → still_there → goodbye
```
- Per-call state (pending confirmation, retries) stored by `CallSid` (in memory or Redis; 10-min TTL).
- `<Say>` is allowed for dynamic parts this iteration; pre-generated `<Play>` for fixed parts where available.
- DTMF fallback in every `<Gather>`: "Say yes, or press 1."
- Goodbye always names the next thing: "See you at the walk at 6 pm!"
- Log every call to `messages_log` (direction, type, transcript), with no audio stored.

**Example TwiML for a confirmation turn**
```xml
<Response>
  <Gather input="speech dtmf" language="en-SG" speechTimeout="auto" numDigits="1"
          action="/voice/turn?step=confirm">
    <Say voice="Google.en-IN-Standard-A">Every day at 8 am, take medicine. Is that right? Say yes, or press 1.</Say>
  </Gather>
  <Redirect>/voice/turn?step=silence</Redirect>
</Response>
```

## 8. Outcome (Thu 12 Nov)

**Inbound call loop (English), done:** `backend/src/bricks_api/routers/calls.py`.
- `POST /voice/incoming`: a known number (users.phone) hears "Hi Mary, it's Buddy from Bricks"
  plus the question and keypad choices (1 today, 2 reminder, 9 help). An unknown number hears
  the language menu in all 4 voices; in demo mode it then carries on as Raj, otherwise
  "not linked yet" and goodbye. 0.1's greeting moved to `POST /voice/hello`.
- `POST /voice/turn`, in this order: (1) distress words in any language, or key 9, raise an
  SOS (`trigger_sos`, trigger "voice") and say "Help is on the way… call 9 9 5"; (2) a
  pending "Is that right?" takes yes / no or 1 / 2 (asked again once, then dropped);
  (3) otherwise today (next reminder plus the next walk, with "Want to join?"), join, remind,
  or bye. Silence: "Are you still there?", then goodbye and hang up.
- The work is done by the app's own functions (`today`, `rsvp`, `create_reminder`,
  `trigger_sos`), so a reminder set by phone shows in the app (marked `created_by='call'`).
- Per-call memory by CallSid, 10 minutes (`calls/session.py`); a restarted server picks the
  call up again from the caller's number.
- Speech language is configurable: `CALL_SPEECH_LANGUAGE` (default en-IN).
- Live sentences in English (`calls/replies.py`); fixed ones are prompt files (4 new ones:
  `menu_keys`, `anything_else`, `not_understood`, `not_linked`).
- Logging: one row per turn in the **shared `messages_log`** from the WhatsApp branch's
  `002_whatsapp.sql` (copied byte for byte; already applied on the live database).
  `route='call'`, the turn kind and the CallSid, never what was said (the WhatsApp rule). An
  add-only `python -m bricks_api.migrate` applies new migrations without the seed's wipe.
