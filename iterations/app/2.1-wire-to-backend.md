## 4. Tasks

### 4.1 API client — `lib/api.ts`
```ts
const BASE = Constants.expoConfig.extra.apiUrl;   // local (ngrok) | demo
export async function api<T>(path: string, init?: RequestInit): Promise<T> {
  const token = (await supabase.auth.getSession()).data.session?.access_token;
  const res = await fetch(BASE + path, { ...init, signal: timeout(10_000),
    headers: { 'Content-Type': 'application/json', Authorization: `Bearer ${token}`, ...init?.headers } });
  if (!res.ok) throw new ApiError(res.status, await res.text());
  return res.json();
}
```

## 10. Outcome (Wed 11 Nov): app side done, waiting on the backend

The real backend isn't running yet, so this iteration built and tested everything on the app's
side; the app switches to the real API when `EXPO_PUBLIC_API_URL` is set. Supabase Auth is wired
to the team project. 359 tests pass; lint, types, expo-doctor 20/20, Android + iOS bundles.

**Built**
- **Supabase client** (`lib/supabase.ts`): session kept in the phone's secure storage, split into
  2 KB chunks (`lib/secureSessionStorage.ts`); refreshes only while the app is open.
- **Every API request carries the member's Supabase access token** (`setAuthTokenProvider`).
- **Google sign-in** (`features/auth/google.ts`): Supabase OAuth in the phone's browser + PKCE
  code exchange, so it works in Expo Go. The Google name prefills S4. `/auth/callback` route
  catches the return link on Android. Sign out also signs out of Supabase.
- **Phone-number sign-in is hidden** when Supabase is on, until an SMS provider exists
  (`EXPO_PUBLIC_PHONE_SIGN_IN`). **Singpass stays a labelled mock** (`POST /auth/singpass-mock`).
- **Offline:** React Query follows the phone's network (NetInfo); a plain-words banner shows on the
  real API; requests that can't connect say "We couldn't connect. Check your internet and try again."
- **Notifications:** a local **8 am check-in** with Yes / No buttons wherever the server can't
  push (Expo Go on iPhone, mock data); Yes answers from the lock screen, No opens the walk
  suggestion. **Push token registration** (`PATCH /me {push_token}`) in our Android build once
  `eas init` has set a project id. Opening a notification reads its screen out (S38).
  Permission is asked at S7 when they choose app notifications.
- **S10 polls every 10 s** while any invite is still waiting.

**Decisions**
| Decision | Why |
|---|---|
| Supabase is used for sign-in only; data still goes through the Bricks API | docs/03 §4: the API checks the token and owns the data. |
| Session in SecureStore, chunked | The plan asks for SecureStore; sessions exceed its 2 KB item limit. |
| Local check-in only where server push can't reach | Avoids two 8 am notifications on Android once the server sends them. |
| No offline banner on mock data | Mock data works offline, so the banner would be wrong. |
