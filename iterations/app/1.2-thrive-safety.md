### 4.2 Walk engine `lib/walk.ts`
Build the final interface now; only the **source** changes in 2.2.
```ts
type WalkSource = 'simulate' | 'gps';
startWalk({ source, eventId? }): WalkSession
session.onTick(({ elapsed_s, moving_s, distance_m, steps, points }) => void)  // ~1 s
session.pause(); session.resume();
session.finish(): Promise<WalkUpload>   // { points[], steps, started_at, ended_at, event_id? }
```
- **Simulate:** replay the Bishan track at real speed; dev-only 10× toggle.
- Filters: drop accuracy > 30 m, jumps > 50 m in 5 s. Distance = haversine sum.
- Steps: `Pedometer` (expo-sensors), falling back to `distance ÷ 0.7 m`.
- **Auto-pause:** speed < 0.3 m/s for 20 s; `moving_s` kept separate.
- `expo-keep-awake` on S22. Persist points to AsyncStorage every 30 s; on relaunch offer "Save the walk you started".
- Mock `finish()` returns a summary in B's JSON shape (computed locally or from the fixture).

**Decisions made (please review)**
| Decision | Why |
|---|---|
| **Walk recording opens full-screen without the tab bar**; Android Back asks "Finish your walk?" | A stray tap can't abandon a walk half-way. Help (SOS) still works on top, and the walk keeps recording underneath. |
| **"Start walk" starts recording immediately**; **Finish asks first** | One tap to start; ending by accident is the costly mistake, so that's the one we confirm. |
| **Auto-pause takes the 20 s of standing back off the clock** | The time shown is walking time, as people expect. |
| **Reminder times are big buttons**; "Another time" uses large Earlier / Later buttons (by hour and by 15 min) | Spinning wheels are fiddly for unsteady hands. |
| **Reminders have visible Done and Remove buttons** (Remove has Undo); no swipe | No hidden gestures (docs/02 rule 6). |
| **The reminders list is the single source of truth for phone alerts**: every time it loads, scheduled alerts are reconciled with it | Reminders set by phone call or WhatsApp alert on the phone too, with no extra code (golden-path step 5). |
| **Permission to send alerts is asked when saving the first reminder**, never at app start | The request comes right after the member chose to set a reminder, so it makes sense. If refused, the Reminders screen says plainly that the phone won't ring. |
| **SOS: 995 first; a 5-second countdown read aloud; Cancel sends nothing; "I'm safe now" asks first** | As specified; the countdown is time-based, so it stays honest if the phone stutters. |
| **SOS statuses say "Priya is on the way"** (not "on her way") | No guessing anyone's pronouns. |
| **Check-in, next event and next reminder are one shared component** on Home, Thrive and S21 | Answer once and every screen agrees ("Well done" on Home after answering on Thrive). After Done, the reminder card says "Done. Well done." and shows the next one. |
| **Android Back on any tab returns to Home** | Never drops a senior out of the app from a tab. |
| **Left out until they can work for real:** voice "Say it" for reminders (Buddy, 1.3), "Share to my Circle" on walks (3.2), Move Along card (2.2) | No placeholder buttons. |
