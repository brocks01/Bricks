# Agent area: browser test script (run in the Browser pane, mobile size, signed in)

No test runner needed: paste the helper into the page console (or the Browser pane's javascript tool), then run each block.
It drives the real screens with pointer events, so it catches what the pure self-test cannot (layout, what is visible, what is on top).
A fake microphone lets the call be tested without a real one:
`navigator.mediaDevices.getUserMedia = async () => { const c = new AudioContext(), d = c.createMediaStreamDestination(), o = c.createOscillator(), g = c.createGain(); g.gain.value = 0; o.connect(g); g.connect(d); o.start(); return d.stream; }`

Helper: find controls by their `aria-label` (Talk, End, "Type a message…", Close), find the drag handles by `touch-action: none; cursor: grab`, and
press with pointerdown, mousedown, pointerup, mouseup, click. Dragging = pointerdown, 14 pointermove steps, pointerup.

Cases (all passed on 2026-11-11, 375x812 and 320x568):
1. Closed: keyboard and call buttons exist, no "Bricks Agent" text, no mic icon, Connect and Grow tabs above the call button, no horizontal overflow.
2. Pulled up 300px: tabs gone, "AI can be wrong" line just BELOW the call button and 12px or smaller, no header text, buttons on screen.
3. Keyboard button: one typing field appears above the call button; tapping again hides it.
4. Call (fake mic): the button turns red with label End, the screen says Listening with an mm:ss timer, the keyboard stays. (The call cuts itself after 15 s of silence.)
5. During a call, type a request: the agent's choices appear INSIDE the chat, the call stays on, no "Generated by" label.
6. Drag the sheet to the bottom with the question open: a pop-up with an X appears, tabs are back, the AI line is in it. A real click on an option removes it.
7. 320x568: everything on screen, no overflow, tap targets 44px or more, the AI line does not wrap.
Needs a real finger or mouse: the drag itself (the script simulates it), and a real microphone call.
