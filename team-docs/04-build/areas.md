# How we build: areas, rules and open work

Read `../01-philosophy/philosophy.md` and `../02-product/tabs-requirements.md` first: they say what Wisdom is and why. This page says **who builds what, in which files, and what is still open**. Several coding sessions work in this one folder at the same time; each owns one **area**.

## Rules for working together in one folder
1. **Own your area's files only** (listed below). Never edit another area's files. If you need a change there, do not make it; write the need in the Status section of your area's product page ("Needs from <area>: ...") and carry on with what you can.
2. **Shared files get one-line, targeted edits, never rewrites:** the router list in `backend/app/main.py`, the import line at the bottom of `backend/app/modules/skills/registry.py`. Use targeted edits everywhere; never rewrite a whole file that another session might also edit.
3. **Migrations:** only your reserved number range (below). Never edit an existing migration.
4. **Keep the app working after every small step.** Small steps, each tested.
5. **Do not start, stop or restart servers.** The orchestrator keeps the API (auto-reload, port 8000) and the web app (port 3000) running. Test the backend with pytest (no server needed) and the app with the checks below.
6. **Git:** commit only your own files: `git add -- <your paths> && git commit -m "<area>: <what>"`. Never `git add -A`, never push, never pull, never create branches. The orchestrator pushes to `main`.
7. **Words:** every user-visible string exists in six languages (English, Hindi, Bengali, Tamil, Chinese, Malay) as a `WordTable` row in your feature's `words.ts` (`[en, hi, bn, ta, zh, ms]`). Placeholders such as `{n}` are identical in all six. Do not edit another feature's words.
8. **Keep the docs true:** when behaviour changes, update the **Status** section of your area's product page (listed below). Do not create new documents except where this page says so. There is no log and no handoff file.
9. **No secrets** (never print, paste or commit keys, tokens, `.env`). **No invented data in the app** (real names and realistic data only; otherwise an empty state). **Never place a phone call; ngrok belongs to the owner.**
10. **Do not stop to ask.** If something is unclear, choose the simplest option that fits the philosophy, and write the choice in your area's Status section.

## Definition of done (every task)
- Backend: `cd backend && python -m pytest tests -q` passes. One test, `test_health_home.py::test_walks_are_saved_listed_and_totalled_by_week`, depends on the time of day and may fail; ignore it. New behaviour has new tests. Migrations apply on a fresh run.
- App: `cd app && npx tsc --noEmit && npx tsx src/navigation/selftest.ts && npx expo lint` are clean. New words in six languages.
- The Status section of your area's page is true. Everything is committed (rule 6).
